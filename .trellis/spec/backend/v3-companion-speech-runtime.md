# V3 selected GPT-SoVITS speech runtime

Status: current task-scoped implementation contract. Model availability, audible functionality, latency and author voice-quality acceptance are separate results. Historical Qwen/Kokoro/v2ProPlus measurements remain in `v3-companion-voice-probe.md`; they do not certify these V2 voices.

## 1. Scope / trigger

Author explicitly selects GPT-SoVITS with Ningguang/Ganyu/Keqing. Only library companionship, sound settings, existing CPU Qwen chat and bounded private workers are in scope. No new microphone, cloud, HTTP listener, training, writing tools, rig change or redistributed character weights/reference audio.

## 2. Signatures

- Public named bridge `companion-voice:prepare(voice: CompanionVoiceId): Promise<boolean>`; owner/main-frame validation matches existing voice operations.
- `configure({textModel:boolean,speechModel:boolean,preload:boolean,voice:CompanionVoiceId}): Promise<boolean>`, `warmup(): Promise<boolean>`, `suspend(): Promise<boolean>` are fixed owner/main-frame methods. Unknown keys/types fail before side effects. `status()` additionally returns independent `textInstalled` and `speechInstalled` booleans; the legacy `installed` is their conjunction, never an all-modes UI gate.
- `CompanionVoiceId = 'ningguang' | 'ganyu' | 'keqing'`; status profile exactly `gpt-sovits-v2-fp16`.
- `CompanionVoiceService.prepare(voice)`, `cancel(owner,session)`, `close(owner,session)`, `clear()`, `shutdown()`. `clear` resets work/session ownership and stops text only; the main-only `shutdown` stops both profiles. No new shutdown IPC is exposed.
- `LocalVoiceRuntime(root,fixedWorker,scheduler?,profile='text',releaseResident?,developerDiagnostic?)`: `run`, `cancel`, `stop`, `available`. `text` accepts only chat/asr/prepare-text, `speech` only tts/prepare. Text availability does not require the deferred ASR asset.
- `LocalModelScheduler.stop(owner?: string)`: optional owner scopes cancellation/release to that owner. Writing scope cleanup passes `'writing'`; it must not release a draining companion request's lease. The existing one active job / one waiter / 30000ms waiter limit remains.
- Explicit setup `download-models.mjs --gpt-sovits-voices`; synthetic private-pipe probe `gpt-sovits-product-probe.ts [--warm] [--verbose]`.

## 3. Contracts

Canonical `gpt-sovits-assets.json` owns pinned source revision, reviewed Python source hashes, G2PW patch hash, asset size/hash, three fixed references and prompt transcripts. Setup reuses the prior pinned 17 audition files and downloads nine selected V2 files (722635596 bytes). Runtime V2 verifies only its required Hubert/BERT/G2PW and selected voice files. Preserve unexpected existing finals; never silently delete older assets.

Separate contained Python environments: existing CPU Qwen/ASR and GPT-SoVITS FP16 CUDA. Directly launch the contained base interpreter from the respective validated venv configuration, `-I -u -X utf8`, hidden/no shell. Environment allowlist excludes credentials and proxies; offline library flags plus socket connect/bind/getaddrinfo audit rejection. `TORCH_FORCE_WEIGHTS_ONLY_LOAD=1`, bounded math threads, `NUMBA_DISABLE_INTEL_SVML=1`; product uses its own `cache/numba`, not the incompatible audition SVML cache. Production discards third-party stderr; only explicit synthetic developer probes may attach diagnostics.

The companion runtime is a portable directory. A `pyvenv.cfg` `home` is usable directly only when the resolved `python.exe` remains inside the current runtime root. After the whole runtime moves, rebase only a strictly version-compatible `cpython-<major.minor>[.<patch>]-windows-x86_64-none` basename into the current root's `python/` directory, then repeat realpath containment. Never search `PATH`, use system Python, accept an unrelated basename, or follow a junction outside the runtime root. The text/local-model and speech profiles share this resolver; startup does not rewrite `pyvenv.cfg`.

For the selected legacy V2 SoVITS files, inspect pickle globals first. Only `utils.HParams` may map to an inert local `LegacyHParams` carrier under `torch.serialization.safe_globals`; never import the checkpoint's class. Load with `weights_only=True`, convert bounded metadata to plain data, reject unsupported types/depth/nonfinite values. Tensor/GPT loads remain weights-only. No unrestricted pickle fallback.

One selected speech engine is resident, not three. Input <=180 chars; prepared text is fixed `欢迎回来。` and its PCM is discarded immediately. No author-text/audio cache. Validated 32kHz mono PCM16 is resampled 3/4 to the unchanged 24kHz PCM16 player/IPC contract. Sentence fragments produce ordered <=24000-byte audio frames; total <=30s/1440000 bytes. Terminal result carries no duplicate audio. Chinese input is the tested profile, not a general multilingual-quality claim.

Latest author override (2026-09-12, verified 2026-09-13): selected GPT-SoVITS speech stays resident for the application session. Settings, blur, chat close, work entry/switch, idle and writing handoff stop obsolete playback/session activity, not the speech process. `clear()` invalidates scope/session and stops text while preserving speech preparation and its engine. `shutdown()` aborts both preparations and stops both owned processes on main application exit or destruction of the owned main window. Text keeps active-cancel termination, the 600000ms idle timeout and scope/handoff teardown. This overrides earlier speech-specific idle/close/disable release clauses only.

Speech `cancel(reason)` rejects its caller immediately, clears deadlines, removes audio/delta callbacks and marks the single pending request discarded. Keep its execution lease until the real terminal frame; validate and discard late PCM rather than publish it. There is no cooperative Torch cancellation protocol in this slice: the already-submitted bounded utterance may finish silently. Never enqueue a backlog, retain chat history/audio for warming, or transfer the execution lease while cancelled inference still runs. `run`'s caller-finally releases only if it no longer owns pending work; terminal/hard-stop releases exactly once. Both companion profiles use scheduler owner `companion` with a text-only resident-release callback; writing cleanup must not clear another owner's active token. No speech idle timer or background heartbeat. Genuine process crashes, invalid frames or broken pipes may still hard-stop that owned worker as a reported fault.

The author-approved optional-model configuration gates the application, not just the player volume. No text model: use `companion-presets.ts` for bounded exact-time/current-page/current-work queries and an honest unsupported-question response. Tap always uses rotating preset lines and a 3s anti-spam interval; hover/night remain grounded rules. These never invoke Qwen. No speech model: never submit new prepare/tts; stop playback/discard pending output but retain any already-loaded engine until exit. A fresh launch with speech disabled loads no speech worker. Both disabled: presets require no Python, Qwen, ASR or GPT installation. Enabled model failure remains failure, not an undisclosed preset/cloud fallback. Settings must disclose continued RAM/VRAM residency and cannot promise immediate resource release when toggled off.

`configure` invalidates old preparation epochs, aborts in-flight responses on model/voice change and clears their history; only disabled text is hard-stopped. Speech off/voice changes discard the old request without terminating its worker; next selected voice is loaded by the existing engine, not three resident voice engines. Turning preload off aborts its pending caller under the same per-profile cancel rules. `warmup` prepares only enabled profiles, text then speech through the existing resource scheduler. Fixed `prepare-text` loads CPU Qwen, performs one discarded token using synthetic `你好`, then resets its context; no deltas or author text. Speech preparation retains the fixed discarded PCM behavior. Per-profile pending preparation is deduplicated. Text-only mode bypasses speech; with both enabled an active cold preparation is joined before chat so it cannot exhaust the scheduler's 30s waiter. Scope exit prevents later stages from starting but permits an already-started silent speech preparation to finish.

Library-owned renderer lifecycle requests warmup while the application opening overlay is displayed, only if its saved preload option is enabled. Latest author override: boot waits for enabled profiles' actual warmup success, then presents a visible ready state for 3000ms before entry; the author can enter immediately once ready or explicitly skip model waiting (not core initialization). No OS startup service, periodic warmup, author-text cache or fake readiness. Renderer observes the existing single preparation owner; no new IPC or worker owner. Proactive reminders skip the opening overlay/initial background preparation and keep the 22s lifetime/no-backlog policy. Deliberate taps show preset text before awaiting speech; the cold TTS caller has a 180s limit and is immediately cancelled on dismiss, long-hold chat, settings, loss of focus or scope exit. Cancelling output is not unloading speech. File installation, preparation and acceptable latency remain distinct. An inter-fragment empty playback queue is not request completion: only a settled response plus fully drained audio starts the 4500ms caption-dismiss timer.

## 4. Validation & error matrix

### Preparation correction (2026-09-12, same task)

`useCompanionRuntime(libraryReady: Ref<boolean>)` must wait for the existing core library load before configure/warmup. Main clears the previous scope before the renderer starts; only a successful `projects:list` reactivates library ownership. Starting earlier can return false without touching Python. This ordering defect is reproducible; it does not prove the author's separate minutes-long failure was the same cause.

Only private speech `prepare` accepts zero-PCM progress frames `{v:1,id,kind:'progress',stage}`. Stage allowlist/order: `verify -> runtime -> weights -> warmup`. They represent actual validation/import/weight/synthetic-inference boundaries, not elapsed-time percentages or a public stream. `PreparationDeadline.advance(stage: unknown)` rejects unknown/backward stages; duplicate stages do not renew the timer. A strictly advancing stage renews the 180000ms stall deadline; a separate 600000ms total deadline never renews. Normal chat/TTS/prepare-text keep the 180000ms request limit. Success, failure and cancellation clear both timers. Timeout terminates text, but rejects/discards speech without unloading it. Discarded progress cannot restart cleared timers. A truly stalled speech worker remains busy/quarantined until its terminal frame, a genuine fault or application exit; subsequent requests have only the existing bounded waiter. No infinite UI wait, hidden retry/restart loop or claim of recovery from a genuine worker hang.

`companionPreparationError(error: unknown): AppError` maps a fixed internal code/stage to bounded Chinese failure copy. `warmup()` propagates that safe error, not `.catch(() => false)`; false remains a non-ready/busy/stale-scope result. Private memory/CUDA/assets categories and process exit are distinguishable. No raw exception text, model path, stack, author text or third-party stderr crosses IPC. Renderer consumes the validated error in both settings and boot. Retry/skip remain explicit; no automatic retry loop or fallback voice. A failure-specific stage is shown; live stage progress is not exposed to the renderer.

Additional cases/tests:

- Healthy ordered preparation lasting 520s succeeds; duplicate stage at 180s stalls; advancing preparation still stops at 600s; cleared timers cannot terminate later work.
- Missing/invalid assets, no CUDA, memory exhaustion, stage stall, total timeout, process exit and cancellation have safe recoverable messages; unknown errors remain generic.
- Library not ready -> zero configure/warmup calls; readiness -> exactly one preparation. Rejected preparation retains its safe message rather than reporting ready.
- Native empty-profile speech-only startup must enter after real preparation, then tap yields actual audible PCM and every source ends before caption dismissal. A successful cold run does not identify an unobserved historical failure.

Wrong: use a single 180s whole-preparation timer, renew it on arbitrary heartbeats, or flatten every exception into false. Correct: bounded real stages plus a hard total cap, unchanged cancellation and a safe failure reason.

- Unknown/old voice, object/path instead of voice, malformed result -> decoder rejection before inference.
- Missing source/patch/hash/CUDA, unsupported pickle global, invalid numeric/audio output -> fixed unavailable error; no Kokoro/system/cloud fallback.
- Same-voice preparation already pending -> join it; other voice or active conversation -> false, no unbounded queue.
- Stale session/owner/sequence, canceled preparation/request -> no late playback or book mutation.
- Speech active cancel -> immediate `VOICE_CANCELLED`, no late audio, same process and lease until terminal. Speech timeout -> immediate fixed timeout error, same drain/lease rule; no later success published. Speech idle cancel/close/work/20min idle -> same process. Full exit -> process gone. Text retains its old active-cancel/timeout/10min-idle/scope teardown.
- Disabled other profile/missing other assets -> no block on enabled mode or preset session. Missing enabled model -> fixed visible error, preserve any returned text; never announce audio success. Switching speech off while loading -> abort caller, discard late output, retain worker; late result cannot start another profile. Switching disabled text off -> abort and terminate text only.
- `scheduler.stop('writing')` while companion drains -> companion lease untouched; queued writing starts only after actual terminal. Clearing writing's own active/queued work -> stop/reject only writing, preserve another owner's waiter even if its stop callback releases reentrantly.
- Incompatible Numba cache -> fail visibly; never hide a crash by reporting ready or disabling weight integrity.

## 5. Good / base / bad cases

Good: open settings during speech, silence immediately, discard old output and retap on the same warm speech PID. Base: initial imports are slow; prepare silently in the enabled foreground library and skip obsolete reminders; RAM/VRAM remains occupied throughout the application session. Bad: fabricate readiness, relabel Kokoro, play warm-up/cancelled audio, retain private conversation history, kill speech on a routine UI event, or start writing inference while abandoned speech still holds the execution lease. App exit must not leave the owned model behind.

## 7. Wrong vs correct

Wrong: `close() { stopAllModels() }`, `torch.load(...,weights_only=False)` as an escape hatch, or `voice:'zf_001'` labeled GPT-SoVITS.

Correct: `close -> endSession`, speech `cancel -> rejectCaller + discardOutput`, `clear -> endSession + stopText`, `shutdown -> stopBoth`; release the speech execution lease only at its terminal frame, not in a cancelled caller's unconditional `finally`. Writing scope uses `scheduler.stop('writing')`. Keep fixed V2 voice IDs, hash-pinned assets, inert metadata conversion and validated/resampled PCM.

Wrong: require `status.installed` before any preset session, or implement model-off only as `AudioContext.volume=0` while still scheduling synthesis. Correct: session availability is separate; main gates new work by decoded configuration. Speech-off stops playback and new prepare/TTS calls; already-loaded speech remains until exit under the explicit author residency override.
