# Process-side quality gates

- New use cases require domain/unit tests and filesystem/provider integration tests.
- Completed writing candidates must survive continued typing: explicitly review a three-way merge against the latest saved prose, never relax revision checks or silently reuse the old full draft. See [writing candidate rebase](writing-candidate-rebase.md).
- Tests use temporary project roots and injected clock/UUID/secret/provider adapters.
- Real AI endpoints are not called in automated tests.
- Fixed semantic evaluation must blind answer-bearing IDs, categories and fixture meta-labels, and avoid answer-alternating order. Send only opaque batch IDs plus narrative evidence, then strictly map every returned ID back to its source before scoring. Persist the delivery protocol, reject missing/duplicate/unknown IDs, and never report fixture provider output or failed credential setup as real model predictions.
- Multi-batch evaluation freezes the actual endpoint, credential, model and sampling profile once, including JSON repairs. Bind the run to its starting book and recheck cancellation/book identity before each request and report promotion. See [evaluation isolation](evaluation-isolation.md) for the commit boundary and regression assertions.
- Task recovery invoked by a feature must filter its own `task_type`; a writing panel must never interrupt a live planning or idea task. Tests retain a queued task of another type while recovering the feature's orphan tasks.
- Durable request replay uses project-scoped idempotency-key lookup, never a capped recent-history list. A polling projection should share one database connection and one source map across all returned tasks; test the connection count and replay with more than 100 newer tasks.
- Successful idea candidates enqueue their readable JSON mirror in the artifact-completion transaction, then synchronize files separately. Old successful tasks can backfill missing mirror records without generation. Tests must cover deleted-file rebuild, external-edit protection, rollback refusal, cancelled-task zero mirror, and SQLite success despite file failure. Mirror retry counts must include every registered source type rather than a hand-maintained subset.
- Prompt/context builders use snapshot tests plus invariant assertions.
- Prior-prose matching may normalize Unicode, but excerpt offsets must map back to the original grapheme positions. Both the initial excerpt and a tighter character-budget crop must retain the matched passage as a verbatim source substring without splitting UTF-16 pairs. Cover expanding punctuation, compatibility ligatures, combining marks, tight budgets, and actual SQLite chunks -> frozen question context; renderer/provider fixtures still do not prove semantic model quality.
- SQL prior-chunk filtering and renderer-independent retrieval scoring share `normalizeRetrievalText` (NFKC + locale-independent lowercase). Register the deterministic, direct-only SQLite function per connection, never as a schema/source rewrite. Materialize the eligible prior/current-version chunks before term matching so normalization runs once per content/title, not once per each of up to 96 terms. Return only original fields; test Unicode hits, title-only hits, current/future exclusion and unchanged version/chunk/schema/mirror snapshots.
- Past-event continuity is not an institutional/capability keyword problem. Shared `narrativeContinuityGuidance` must reach prose generation (fast and reviewed), selection edits and read-only review/query without adding requests. Test actual captured provider instructions, unchanged one-request fast behavior and read-only zero candidate. Separate contradicted claims from missing evidence; candidate text, future prose and planned events are not evidence of a past occurrence. A prompt-injection regression passing does not establish semantic accuracy or complete-book retrieval. Real-book audits use read-only current body pointers, record coverage and version fingerprints, and require item-level author approval before prose changes.
- Migration tests hash source fixtures before and after.
- Legacy developer file writers must reject SQLite formal or unreadable/unknown mode before credentials, provider calls and project writes. File/shadow use requires explicit offline acknowledgement and no concurrent app writer; recheck before long-running output is promoted. Never hardcode a live author book as the default mutation target. Test real command refusal plus unchanged database bytes and junction escape; an entry guard is not a cross-process transaction lock.
- Planning readiness tests must cover a book with no author note or source cards: candidate-only ideas cannot start generation; approved ideas and approved formal entities can. A promoted idea is replaced by its formal target in planning context, never by later edits to the source note. Verify all generation stages receive that canon and no candidate generation mutates formal outlines.
- IPC contract tests verify allowlisted methods and schema rejection.
- First chapter-outline saves must be tested on a newly created manuscript, not only an imported outline. Planning passes the author's chosen volume through DocumentService to SQLite for creation; existing stage ancestry must survive ordinary saves. An unassigned new outline fails with an actionable hint rather than inventing a parent. Cover both explicit volume input and a previously persisted placement, with unchanged body and readable mirror assertions.
- Long work runs outside the main event loop and supports cancellation.
- Required gates: lint, typecheck, unit, integration, E2E and desktop build. A small foundation test suite is never reported as full validation.
- Idea-to-summary promotion uses the existing summary/total root, never a duplicate root or an implicit overwrite. Commit the source link and outline version together; later source edits/status changes cannot replace the formal summary in planning context. Verify a v20 database retains exact idea rows after migration and rejects invalid promotion targets.

Per-chapter detailed-outline adoption requires all of: a zero-write preview assertion, a stale-preview conflict assertion, an exact one-chapter write assertion, an unchanged-manuscript assertion, strict IPC decoder coverage, and a real Electron click through both preview and confirmation. A service-only test is insufficient because modal wiring and structured-clone payloads are part of the failure surface.
