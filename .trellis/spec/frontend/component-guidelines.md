> V3 status: `candidate-for-v3`. This accumulated V1/V2 component and visual rule set is evidence only. Use the active V3 renderer specs.

# Component guidelines

- 作者原稿布局使用逻辑比例：组件字级/图标/间距来自共享 rem/em 令牌，首页分栏使用 fr 和容器 clamp；写作侧栏按整行预算适配，窗口变化不重写用户偏好。仅换单位但继续固定每个组件的宽高不算响应式修复。可伸缩的目录容器须显式按内容排布行，避免少量章节被 grid 默认 stretch 拉成长空白块。原生截图须覆盖实际应用缩放和根字号变化，不得把 Windows 截图像素倍率当成应用缩放。

> 最新视觉依据（2026-09-08）：作者直接提供两张界面 PNG 与两套 loader HTML，并明确要求开发。`design-system/approved-2026-09-08/IMPLEMENTATION.md` 优先于本文件下方历史 Superdesign/卡片/助笔内角色的外观规定；安全保存、确认、导入、只读数据等业务约束仍然有效。作品库采用左立绘、右档案管理；写作角色位于全局顶部，助笔不含角色；正文工具直达、保存和历史位于底栏。大标题和头像须在真实 AppShell 的多层样式中截图验证，不能仅靠孤立组件的 CSS 或 SSR 测试。

- Views orchestrate feature state; reusable components receive typed props and emit semantic events.
- 快速打开章节使用当前作品已加载的章节索引和显示章序，不把稳定 ID 当章号。Ctrl+P/Meta+P 不抢其他模态、载入或中文组字；原生 dialog 提供 Esc/关闭、焦点返回、空态及完整结果访问。导航回调必须等待既有保存保护、校验当前作品身份、读取正式章节后再切换；保存失败保留原章节和草稿，不以快捷入口绕过保护。布局沿用相对尺寸与主题令牌。
- Workflow guidance names one next action with an explicit native button; status labels remain plain text. Conflict dialogs explain modify/ignore/later outcomes and preserve a discoverable return path after closing. Scrollable grids containing overflow-hidden evidence cards use content-sized rows to avoid silently clipping headings or actions.
- 创作指引与助笔核对必须使用同一当前章节阻断项；attention / deferred 不得成为必须完成的下一步，无阻断时突出继续写作。未检查不能写成已通过；非 ready 项必须保留可见原因说明，不得用全局 small 隐藏规则只留下无语境按钮。纪事入纲的可选整理链接到总纲事件关联，不能回纪事制造重复确认。
- 正文候选逐块选择不是正式采用：必须显示未写入状态、采用数量及保存后果。未决定时主动作可定位下一处选择按钮，不得发出采用事件；选完后才使用“写入正文并保存”。正文变化不禁用整份已完成候选，改为“与最新正文合并核对”；作品/章节身份或章卡依据变化仍保护。候选卡内的操作区不得覆盖逐块比较与选择控件。
- Components do not call `window.novelDesktop` directly. Feature composables call a typed client wrapper.
- Every async panel implements loading, empty, error, success and recovery states.
- Destructive controls state the affected local files and require confirmation; default project removal means “remove from shelf”.
- Writing components separate manuscript, AI draft and revision diff so AI output never silently replaces text.
- Form labels, keyboard focus, contrast and reduced-motion behavior are mandatory.
- Use local fonts/assets only; the UI must not fetch cosmetic resources from the network.
- 高影响人物冲突使用证据案卷：必须同时显示人物、章节位置、字段、模型声明、正文逐字证据和操作后果；“认定为误报”是有边框的明确按钮，关闭面板表示保留待办，不能把关闭当成驳回。
- 详细章纲候选在原单案面内展示“候选 / 已写入正式章纲·待复核”的可读状态。采用使用有标题、当前内容、候选内容和影响清单的确认纸笺；页面底部只保留一个明确的下一章主操作，不新增重复导航页或批量采用按钮。
- 作品库必须把“新建空白作品”“从外部文稿建立新工作项”“打开已识别的岚笺作品”表现为三个不同动词入口；不得用泛化的“打开项目”同时承担目录打开与文件导入。
- 作品库遵循 2026-09-07 最新确认：首页保留顶部搜索、左侧全部作品/已归档/系统回收站和继续写作区，作品使用自适应多列卡片，不再显示“最近打开”分类或横向表格。使用独立 ProjectLibrary 展示组件，保留原有打开、导入和破坏性操作处理器；卡片管理菜单独立于打开按钮，不能被相邻卡片遮挡或超出视口。归档仅是本机书架分类，不能移动正文或代替系统回收站。
- 从外部文稿建立工作项时，界面必须在确认前说明正文、作品相关资料、原文件归档、模型候选与正式事实各自落点；模型建议不得与导入成功使用同一个确认语义。
- 旧项目迁移诊断必须把阻断、待核和说明做成有边界的证据项；不可迁移时不显示伪可用主按钮。当前岚笺作品直接打开，不展示补全仪式。
- 对用户统一称“文稿/文件”，并明确列出当前支持 TXT、Markdown、Word `.docx`；内部历史 API 名称不得泄漏成产品文案。
- 多文件接续必须逐文件显式选择用途，不把系统建议预选成作者确认。文件间安全中断后，界面复用已经建立的书案并显示“继续未完成导入”，不得再次创建同名项目或重复已完成正文。
- 重开作品时，未完成导入在当前书案侧栏以进度卡恢复；安全的 pending 批次提供有边框的明确“继续导入”按钮，可能部分落盘或日志损坏的批次只显示人工核对原因，不制造伪可用按钮。
- 旧稿接续分析留在“作品定义”单案面：顶部先显示硬缺口/冲突/建议计数，九类候选使用可编辑纸笺并可展开逐字证据。保存候选是有边框的明确按钮，文案必须说明不会写入正式设定、人物记忆或三级大纲；正式采用另走逐模块影响预览。
- 旧稿候选采用必须“一项一核”：预览同时显示当前值、候选值、唯一写入范围和明确保留项。按钮使用动作文本而不是可点击文字外观；预览后数据变化必须关闭旧纸笺并要求重新核对。
- 旧稿章纲采用必须先显示已有章节选择器；只列出已归入接续卷且父级总纲/卷纲已确认的章节。采用后唯一下一步是打开现有章纲案边复核，不复制新的审核面板。
- “已有剧情”不能用一个按钮采用整段模型摘要。影响纸笺必须要求作者补齐时间、人物、地点、事件四维，并可展开逐字证据；确认文案明确“只确认这一项纪事”，其他候选继续保持未采用。
- “人物”候选必须逐人立传：先填写姓名、初始定位和人物弧方向，再显示新建/补充/更新/一致影响；唯一确认动作写明“只确认这一人”。页面必须同时说明正文动态状态不变，不能把模型摘要伪装成批量人物卡。
- “总纲碎片”只能在六类前置事实确认齐备后开放。影响纸笺必须显示当前/候选、总纲版本与确认状态、已有卷纲/章纲数量；唯一主动作写明“只采用为正式总纲”，并明确采用后仍待复核、不会生成下游内容。
- 接续总纲采用后不得继续把“重新采用”当成下一主操作。候选卡应直接交接到唯一正式总纲编辑器并展开既有结构检查案边；正式确认状态只能来自 outline Gate，不能从采用回执推断。
- 接续卷纲不得自动猜卷或代建卷。作者必须从当前篇卷目录的明确下拉选择目标卷；采用后唯一主动作进入既有卷纲编辑器与结构案边，正式确认继续来自该卷 outline Gate。
- 章节本地事实包复用智能助笔右栏的默认折叠证据簿，不新建 RAG 页面。折叠态显示“当前书、当前章之前”、证据数和字符预算；展开项显示章序、标题、正文版本、逐字摘录和命中原因。
- 事实包是只读证据，视觉层级低于一致性 Gate。切书清空；侧栏关闭时不扫描；同一章节与上游状态未变化的普通工作流刷新复用当前结果。
- 展开后的同一证据簿按创作约束顺序只分三组：本章正式事件、章前人物状态、前文逐字证据。显示稳定 ID、事件来源、状态截至章和最后事件，但不在只读案卷内增加编辑、采用或第二套导航按钮。
- 章节证据簿使用独立只读组件：壳层只传入 main 已投影的 `ContextFactPackView`。组件不得调用 preload、重读 canon、持有作品身份或发出编辑/采用事件；测试定位属性是 Electron 回归契约的一部分。
- 一致性总览使用独立展示组件：只接收 main 总览与壳层候选摘要，并发出语义选择事件。人物证据读取、模块导航和滚动目标属于壳层副作用，不得藏入展示组件；每个状态行继续使用原生按钮和文字状态，不能只靠颜色表达。
- 长篇章节树对作者呈现为按正式卷章顺序的连续滚动目录，不得显示“前 120 章 / 后 120 章”或其他固定批次切换。搜索必须覆盖完整章节事实源，当前章可自动定位，清空搜索恢复原序；目录投影与搜索不得读取正文、重排章节或持久化第二份章节状态。
- 正文编辑器使用组件本地草稿承接高频输入。中文输入法 composition 开始时必须取消待执行的父级同步；任何切章、切面板或关窗 flush 必须等待 `compositionend` 后读取真实控件最终值，组件卸载不得提交组合中的半成品。
- 1–3 万字正文的每键热路径不得通过 `match()`、`split()` 等方式构造全稿词条或行号数组。统计与定行可以线性扫描，但需共用一份投影并有长章数量级回退测试。
- 章节写作 Agent 使用连续消息线程：用户要求、AI 回复、运行状态、候选正文和只读工具依据按轮次留在同一滚动区；底部输入框在空态、运行态和结果态始终可用。技能选择只能作为输入框的临时菜单，不得用互斥页面打断对话；候选采用继续绑定对应回复并保持显式确认与过期门禁。
- 章节写作 Agent 的模型选择位于 composer 工具栏，使用共用 ModelCatalogPicker 分类目录并默认跟随任务分配；支持当前接口已探测/已分配模型及作者手动输入的模型 ID。未分类模型保留为“其他”，同名模型按 `(connectionId, model)` 区分。手动条目保留本次完整路由，不能因未出现在目录而回退默认模型；覆写不持久化第二份设置。运行态和完成回复显示实际模型，main 仍验证所选接口并使用本机密钥。
- 智能助笔的可见性、切换按钮、网格占位和只读事实包刷新必须共用同一可用性判定；设置、作品定义、创作筹备等无助笔页面不得留下空列或无效入口。章节目录属于正文主导航，在普通写作模式下必须持续可见；较窄桌面窗口通过收窄目录与助笔形成四个互不重叠的网格列，不得隐藏目录或覆盖正文。
- 作品书架拥有独立顶栏、分类侧栏和内容网格，任何正文/助笔响应式规则都必须显式排除 `library-mode`；不得因为无助笔状态把书架内容挤进活动栏宽度。
- 全局中文字体只使用 `LanjianSerif` 与 `LanjianSans` 两个角色：书名、页面题名、章节标题和长文归 serif，按钮、输入、目录、标签与状态归 sans；别名必须优先本地 Noto/Source Han 并声明可用字重，不得在页面内另写 Georgia、SimSun 或远程字体。
- 普通保存动作统一使用 `control-button primary save-action`、保存 SVG 和明确动词；密集编辑器可使用紧凑高度，但颜色、圆角、禁用、保存中和失败重试语义不得另起一套。助笔与正文不得发生任何几何覆盖。
- 2026-09-07 的融合视觉仍是历史证据；V3 当前框架以 active `v3-workspace-navigation.md` 为准。顶部只保留“智能助笔”，任务能力留在助笔任务子页；composer 控件不足一行时换行，不缩成难辨的模型/接口字样。设置的模型分配切换整组换行，不能把单个按钮文字压成两行。
- 作者随后明确以 Superdesign 当前画布为主（远端 v5），不能用仅匹配颜色的旧结构冒充落实。正文搜索/新增/更多放在章节栏首部；`ChapterTreeList` 用可选 `query` model 与 `externalSearch` 保留同一全量搜索/窗口算法，切书或离开写作时清空外置查询。保存、历史与真实保存状态只在顶部出现一次，底部保留统计和章状态。窄编辑区域按自身容器宽度压缩次要入口，保留可读保存按钮及图标的可访问名称；不能靠把工具栏无限换行来通过“未遮挡”测试。
- 紧凑写作窗口的四列必须按总宽度预算：`可用宽度 - 活动栏 - 章节栏 - 助笔栏`，而不是分别限制两侧栏后让正文承担全部缺口。在 1100 原生窗口、125% 应用缩放的用例中，为 workbench 预留 420 CSS px；只钳制渲染宽度，不覆盖 localStorage 中作者保存的宽度。恢复大窗口须回到原偏好。助笔标题栏不可同时固定高度并允许换行；低于 320px 时用标题/关闭一行、三个标签一行，保持关闭和模式按钮可点击。
