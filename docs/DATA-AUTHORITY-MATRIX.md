# V3 数据权威与文件角色矩阵

> 文档角色：V3 数据权威与回退契约，服从[V3 产品基线](PRODUCT-BASELINE.md)。本文件只晋升跨版本仍有效的数据安全不变量；当前工程约束见 [V3 数据安全规范](../.trellis/spec/backend/v3-data-safety.md)。精确 schema、服务名和候选功能规范仍须由后续 V3 任务逐项接纳，发现偏差时停止写入性变更并进入 Trellis 协调任务。

2026-09-18 已批准正文/大纲改为文件权威，实施任务为 `09-18-v3-file-first-manuscripts`。新模式的当前正文/大纲来自作者可读 Markdown；SQLite 保存结构化数据和文件引用；历史文本在独立文件快照，不是数据库全文。当前迁移仍在实施，下面旧 SQLite 内容/镜像条款仅用于尚未成功迁移的作品和未改变权威的结构化模块，不能据文档标签直接切换作者数据。

文件权威保存须校验实际文件修订、原子替换并保留跨文件/元数据失败恢复凭据。元数据写失败不允许旧库覆盖新文件；缺失文件显式报告并从历史恢复，不伪造空稿。迁移保留当前稿、所有历史及未完成草稿，逐项校验后才切换，备份保留。AI 候选、上下文留证与正式正文副本是不同角色，不清除有效来源证据。

## 角色与允许的数据流

| 角色 | 典型路径 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 当前正文/大纲（新模式） | `正文/*.md`、`大纲/**/*.md` | 保存作者当前可编辑的正式文本；经修订校验后原子替换 | 作为 SQLite 镜像被后台覆盖；缺失时从旧库静默补写或返回空稿 |
| 结构化正式数据 | `.webnovel/workspace.sqlite` | 保存身份、顺序、层级、章卡与确认、人物/事实/事件/设定、模型路由、任务来源及文本文件/版本引用 | 在 `files-v1` 中重复保存完整正文/大纲，或用元数据失败回滚已落盘的新稿 |
| 不可变文本历史 | `.webnovel/history/text/<sha256>.md` | 保存正文、大纲、检查点和检索分块所引用的不可变内容；支持版本查看与显式恢复 | 充当第二份当前稿；普通打开时覆盖当前文件；丢失时被跳过 |
| 启动入口 | `.webnovel/state.json` | 识别旧项目、提供尚未切换作品的标题与迁移信息、随备份恢复新副本 | 正式模式下改写书架名称、题材或任何故事事实 |
| 结构化可读镜像 | `.webnovel/config/*.json`、`.webnovel/planning/chapter-cards/*.json`、`.webnovel/planning/outline-state.json`、`.webnovel/research/*.json`、`.webnovel/story-state/*.json`、`.webnovel/ideas/ideas.json` | 在结构化 SQLite 提交后重建或同步；让作者直接阅读和备份 | 被外部修改后静默覆盖数据库；出现冲突时继续假称已同步 |
| AI 候选 | `.webnovel/ideas/generations/*.json`、`.webnovel/planning/expansions/*.json`、`.webnovel/planning/automatic-planning-draft.json`、`.webnovel/imports/continuation-analysis-candidate.json` | 保存可丢弃、可复查的模型输出和来源 | 未经预览、版本校验和作者确认成为正式设定、大纲或正文 |
| 导入证据 | `.webnovel/imports/index.json`、`.webnovel/imports/manifests/*`、`.webnovel/imports/sources/*` | 记录原文件 hash、作者指定角色、选择范围及恢复进度 | 被当作当前正文、大纲或事实权威；重复提交已完成导入 |
| 本地恢复 | `.webnovel/recovery/*`、`.webnovel/config/recovery/*`、`.webnovel/planning/recovery/*`、`.webnovel/history/chapters/*` | 在异常退出、冲突或迁移前保留可人工核对的副本 | 自动覆盖当前正式版本；跳过一次性预览和版本匹配 |
| 派生报告 | `.webnovel/evaluations/*.json` | 展示固定样本评测与真实试跑记录 | 进入正文生成上下文，或反向产生正式事实和设定 |
| 字段助笔候选历史 | 应用 `userData/field-assistant/<作用域 SHA-256>.json` | 按作品/应用分区保留最近 100 项候选、模型和回填/撤销记录；损坏时保留原件并报错 | 成为正式作品权威、自动回填旧会话或冒充作品备份的一部分 |

作品定义显式保存时，已核验的字段候选来源写入原配置扩展 `fieldAssistantSources`，与版本校验后的定义同时提交；字段候选本身不因此成为事实账本。其他字段保留应用候选回执，并沿用各自页面的正式保存/批准机制。具体契约见 [V3 字段助笔](../.trellis/spec/backend/v3-field-assistant.md)。

## 正式模式的不变量

地图坐标沿用以上边界：正式切换后的地图记录属于 SQLite 权威，`.webnovel/config/world-map.json` 只可作为可读镜像；旧模式兼容读取文件，明确保存才可建立地图模块。坐标是作者标注的显示布局，不是自动确认的新地点事实。当前具体 schema、服务和 UI 仍是 `candidate-for-v3`，等待 V3-5 任务接纳。

1. `files-v1` 正文/大纲先校验并原子保存当前 Markdown，再用持久操作凭据提交元数据；结构化模块和旧 `legacy-sqlite` 文本仍先提交 SQLite、再同步可读镜像。
2. 文件权威保存发现当前修订已变时拒绝覆盖；结构化镜像或旧文本镜像 hash 不一致时标记冲突。两者都不能按修改时间猜测新旧。
3. 文件权威当前 Markdown 的外部修改按实际修订读取；采用历史、恢复稿或 AI 候选仍须只读预览、当前作品/版本校验和明确确认，并建立新的追加版本或来源记录。
4. 项目名称与题材在正式模式下从 SQLite 读取；`state.json` 与 `book-profile.json` 的外部修改不能改变书架显示的正式身份。
5. API 密钥只存操作系统加密设置，不进入 SQLite、项目 JSON、备份清单或模型上下文。
6. 候选、任务、导入证据和评测报告损坏时，可以锁定对应辅助功能，但不能因此改写仍可读取的正式正文。
7. 启动、状态和结构化镜像读取必须在 SQL 层限定目标类型；不得先物化整本正文/大纲历史再在 TypeScript 中过滤。只需要章序/身份时使用元数据查询，不读取正文。

## 版本化事件的权威边界

- 已切换事件模块在同一 SQLite 权威中记录事件稳定身份、不可变内容版本和来源；宏观计划、章节细节与正文实际是分层视图，不各自复制一份可并发编辑的权威。
- 事件批准状态与是否已在正文发生分别表达。旧资料无法证明其粒度、计划/实际阶段或大纲来源时保留未知，不通过迁移猜测。
- 来源记录回答“从哪里产生”，依赖快照回答“依据哪个版本仍然有效”；只有明确的依赖参与过期传播。章纲联合采用在一个正式事务内绑定新事件版本，镜像同步在提交之后进行。
- 数据库结构升级可以准备版本表；旧事件内容建立版本基线和旧直接纪事转入统一事件轴均须显式写入，不能在只读打开/预览时暗中执行。旧文件与尚未切换模块保持兼容读取，统一迁移须经预览确认。
- 第一切片只交付版本/来源底座；正式统一时间线、跨层依赖执行、章纲联合采用和正文结算的产品入口由后续切片逐项验收。契约见 [V3 事件与谋篇一致性](../.trellis/spec/backend/v3-planning-event-consistency.md)。

## 全局模型连接与作品选择

- 本机全局连接库和新书默认分配属于应用设置，不属于作品事实；接口元数据与操作系统加密凭据由同一安全应用存储提交。密钥、密文及本机可用状态不进入作品数据库、镜像、备份或候选。
- 作品只持有明确作用域的连接引用、型号和参数；正式作品仍由 SQLite 管理这些选择。创建时继承是版本副本，不是随应用默认实时变化的第二份作品权威。缺少本机连接时保留原选择并提示重新绑定，不阻止正文编辑。
- 旧接口加入全局库须预览确认且可重试；原书配置和原凭据保留。加入与作品改选是两个独立操作，不宣称应用文件和作品数据库具有跨存储原子事务。读取不触发迁移，损坏不退回空默认，删除作品不删除共享连接。

## 回退边界

旧 `legacy-sqlite` 作品的兼容回退须确认所有正式镜像已同步且无冲突。`files-v1` 已把当前文本交还作者文件，不允许原地降级回旧正文权威；恢复通过已验证的新副本或显式历史恢复完成，不删除 SQLite 结构化数据、历史、候选或证据。

## 旧开发脚本边界

迁移前的正文批量生成、章纲登记和模型探测脚本不得在 SQLite 正式作品运行。旧脚本及其门禁实现均未被 V3 接纳；在后续任务证明其身份、路径和并发保护前，应视为不可信写入入口并保持禁用。文件/影子模式也不能仅凭旧说明恢复运行。
