## 1. 产品定义

岚笺是一款面向中文长篇小说作者的本地桌面创作平台。它把作品资料、设定、四要素事件、分层大纲、正文、人物状态和一致性证据组织在同一本书中，并在作者主动请求时提供可审阅的 AI 写作协助。

产品使用 Electron、TypeScript、Vue 和 CodeMirror 构建。作品与项目数据保存在作者选择的本地目录；不要求产品账号、登录、云同步或远程项目存储。

## 2. 核心用户结果

- 作者能够新建、打开、导入、迁移、备份和恢复一本本地作品，而不被隐藏格式或云服务锁定。
- 作者能够从作品定义、素材和设定出发，按“全局总纲 → 卷纲 → 全书章节骨架 → 章纲 → 章节正文”的总分关系持续创作；版本化事件时间线贯穿各层，先提供宏观约束，再随章纲细化，并依据正文证据结算实际发生的事件。
- AI 输出始终是有来源、可比较、可舍弃的候选；未经作者明确采用或确认，不成为正式设定、大纲、事件或正文。
- 长篇写作可以追踪人物、地点、时间、事件、关系、境界、知识和伏笔的变化，并能定位到对应章节与证据。
- 叙事档案终端、写作伙伴、桌宠、人物档案和沙盘地图使用同一作品事实，不各自制造互相矛盾的数据。

## 3. 核心创作闭环

1. **作品建档**：新建空白作品，打开既有岚笺项目，或从 TXT、Markdown、Word 等外部文稿安全接续。
2. **资料与设定**：整理自备资料、外部参考、作品定义、世界观、力量体系、境界表和金手指/特殊优势。
3. **正式纪事**：同一事件轴提供宏观计划、章节细节和实际事件视图；事件必须具备时间、人物、地点、事件四个维度，以稳定身份和追加版本演进，保留来源。作者批准一个计划不代表事件已经发生；模型提取结果先作为候选逐项确认。
4. **谋篇**：总纲与宏观事件相互校核；总纲约束卷纲，卷纲约束全书章节骨架和详细章纲。章纲可以扩展计划事件，采用时一并提交章纲、选择的事件版本和来源依赖，使新章纲直接绑定新版本。上游变化沿实际依赖关系使下游明确过期；细化引起的上游矛盾交由作者复核，不自动回写。保存、采用和正式确认仍分别表达不同的作者意图。
5. **成文**：正文编辑优先保护中文输入、自动保存、历史版本、恢复和作者手写；AI 生成在独立候选中预览与采用。
6. **审校与结算**：确定性 Gate 检查结构、版本和显式约束，模型评审提供语义问题候选；二者不宣称保证任意自然语言绝对一致。正文保存/采用后，人物与实际事件才可依据该正文版本的逐字证据提出结算，作者确认后区分计划的实现、偏离和新增；正文改写使基于旧版的结算需要复核。

## 4. AI 写作伙伴

- 写作能力以插件提供统一工具接口，内置能力与作者安装的自定义插件均可由 AI 根据当前创作目标选择调用。自定义插件支持编写新的工具代码，也支持提示词与已有能力组合；作者可以管理安装、启停、升级和卸载。插件复用应用提供的作品与模型能力，不能自行扩大数据访问范围、取得密钥或绕过正式内容采用规则。
- 向作者提问、提供单选/多选和接收自由输入也是可调用的工具。任务在需要作者决定时明确等待，取得真实回答后继续；未回答、取消、失效和失败不当作同意或完成。剧情偏好回答与正式内容采用分别表达作者意图。

- 在线模型接口由本机应用统一管理，密钥只需安全保存一次；作品独立选择谋篇、章纲、正文和审校的连接、型号与参数。新书在创建时复制作者设置的默认分配，之后修改默认不改变已有作品；共享接口不共享书稿、上下文或采用权限。
- 旧书接口经预览确认后可加入全局接口库，不自动改写原书分配或删除原凭据。更换共享密钥、停用接口须明确其跨书影响；地址变更使用新连接，不能把旧密钥静默发送到新地址。无默认或接口不可用不阻止手写；模型失败不自动换接口。

- 智能助笔在作品内每个页面可达，作品库及其新建表单不显示助笔；定义、素材和设定辅助不要求先有章节。作者通过单一聊天框表达目标，由模型调用工具定位和读取内容，核对修改后采用回填，继续编辑或撤销；显式保存表单保留未保存状态，正文沿用正式候选与版本采用流程。
- 智能助笔的已开放工具作用于当前作品，不能由当前页面限制。需要其他创作工作区时自动定位并继续原任务；通过有界 Agent loop 检查结果并继续必要步骤，直到目标完成、需要作者决定、被停止或明确失败，不能把单次回复或步骤耗尽当作完成。独立测试小说可生成明确标记为未写入正文的对话样稿；正式作品创作仍遵循总纲、事件、章纲和正文的层级及采用流程。
- 字段辅助绑定当前作品、对象、字段及草稿版本；密钥、只读证据、路径与正式确认授权不成为模型可写字段。页面访问或输入聚焦本身不调用模型。

- 写作助笔仅在作者主动发起生成、问答或审校时调用作者选择的 OpenAI-compatible API 或受管本地模型。本地模型商店统一展示模型资源、检测状态与模块适用能力；已安装模型可分配给谋篇、章纲、正文与审校，后续通过受控下载/安装适配器提供一键准备。看板娘可另用作者主动启用的本地小模型问答与语音，不继承写作助笔的工具或采用权限。
- 本地模型当前作为 Beta 能力，已有 Qwen 用于验证模型与工具调用流程；长文篇幅和创作质量不作为该 Beta 接入的完成门槛，也不宣称该小模型适合正式正文生产。运行失败仍需明确反馈，不能误报成功或自动采用。
- 每次请求只读取当前作品、当前任务所需的已确认事实、有效大纲、人物快照和有来源的历史正文证据。
- 题材策略可以分别影响谋篇、章纲、正文和审校提示词，但不能关闭 ChapterContract、一致性 Gate、跨书隔离或数据安全规则。
- 正式章节生成只使用完整流程：前置依据与章契检查、正文候选、章契/事实边界审校、本地完整性检查、作者核对采用；移除旧版快捷生成入口和运行分支。旧偏好不重新启用快捷路径，历史候选保留原检查标记，不冒充已经通过完整审校。
- 动态境界从当前作品的正式配置读取；写作与检查必须遵守等级、能力边界和突破条件。
- 系统流/金手指描写使用作者配置的固定显示模板；AI 不得随机改变面板字段或排列。
- 聊天历史、检索结果、模型总结和评测报告都不是小说 canon；只有作者确认的正式内容能够成为事实源。

- 完成文件权威迁移前，旧正式作品仍以 `.webnovel/workspace.sqlite` 为内容权威；不得仅修改模式标签或直接把可能过期的镜像当成最新稿。其他结构化模块及其 JSON 镜像契约不变。
- 尚未迁移的文件模式或未切换模块继续按已验证的兼容路径读取，迁移必须预览、校验、可恢复且由作者明确确认。
- 文件权威正文先安全落盘，再更新元数据，失败保留可恢复凭据并显示真实状态；历史快照与当前文件分开。旧 SQLite 权威和结构化模块仍先提交数据库、再同步镜像。任何模式的外部冲突都不得静默覆盖。
- AI 候选、导入证据、恢复稿和评测报告不能反向覆盖正式内容；采用时必须复核当前作品、目标、版本和内容指纹。
- 作品正文、设定和凭据不得因应用更新、UI 重构、测试或文档整理被删除或改写。
- API Key 只存操作系统加密设置，不进入作品数据库、镜像、备份清单、日志或模型上下文。

### 6.2 独立桌面宠物

- 2026-09-18 作者确认：打开作品默认不加载独立桌宠；只有用户主动开启后才加载，并记住开关供重进作品和重启使用。没有明确开关的旧设置按关闭处理；返回书库或专注自动收起不改写选择。此规则不改变作品库页面内看板娘和语音预加载设置。
- 宠物是独立、透明、最小权限的桌面窗口，可以拖出主窗口、跨显示区域移动、切换普通/Q 版、控制穿透、隐藏与找回，并记忆安全位置。
- 宠物只接收不含正文和密钥的展示状态，不直接读取或修改小说数据。
- 首批互动为摸摸、骰子、灵感签和默认关闭的休息提醒，全部本地运行，不暗中调用模型。
- 精细形态复用作者确认的本地 Live2D Cubism 资产；作品库页面内看板娘与进入作品后的独立桌宠可以共享模型和安全动作集，但宿主、权限与显示时机必须分离。正式 Q 版图片仍由作者后续提供；静态或 CSS 轻动态立绘不得冒充 Live2D。

### 6.3 人物档案与小说沙盘

- 人物视图分离稳定身份、正文形成的动态状态、关系陈述、出场章节和证据；同章出现不能自动推断关系。
- 沙盘地图复用正式地点、事件、人物和章节关联。二维位置是作者标注的显示坐标，不是经纬度、真实距离或自动确认的新地点事实。
- 人物档案、关系图、事件时间筛选、章节导航和地图共同读取同一事实链。
- 纪事主入口为“事件 / 地图”；伏笔备忘和人物状态作为辅助工具，卷概览归入谋篇，保留原有数据与来源核对能力。
- 2026-09-11 作者要求二维地图仅保留其提供的米白纸雕、深玉绿海洋与微缩地标提示词，撤下其他风格生成入口，已采用旧底图仍可读取。地点和建筑用途来自本书，不注入示例地名；真实三维独立标为 Beta，后续完善。
- 纪事使用窄档案侧栏，事件与地图为主要入口，辅助工具必须有明确按钮形态。地图画布优先，生成配置与章序筛选按需展开；读取地图不得阻塞离页，未保存内容和正式写入仍受保护。
- 2.5D 地图、角色详情舞台和正式分层角色资产在基础数据联动稳定后渐进提供，并按设备能力降级。

4. 作者手写不因模型失败、任务取消、应用重启或候选过期而丢失。
5. 正式正文和状态只使用当前时点可知的批准事实，不能提前引用未来章节。
6. 时间、人物、地点、事件四要素贯穿纪事、章纲、正文检查与可视化。
   - 事件来源追溯与有效性依赖分别记录；“从章纲提取”不能自动成为使章纲自我过期的循环依赖。
   - 时间线、地图、谋篇和模型上下文共享正式事件身份与版本；章序、故事发生时间和人物获知时间分别表达，倒叙/插叙不能造成未来事实提前泄露。
7. 动态境界与固定系统 UI 模板在生成上下文和一致性检查中强制生效。
8. 测试、演示、截图和原型只能使用隔离数据，不能冒充作者真实体验或正式产品完成度。
