# 发布流程

1. 从 main 创建发布分支，在独立目录按明确路径同步已审查源码。
2. 检查源文件、可达 Git 历史和资源许可，排除私人任务、小说、密钥和生成产物；运行 Gitleaks。
3. 统一 desktop/package.json 与 lock 的版本。保留 appId、协议和既有数据身份。
4. 运行共享包、桌面、网页、托管与所发布服务的检查。构建 Windows x64 安装包。
5. 使用临时安装位置、独立 userData/全局模型目录与合成作品做安装、启动、手工保存、正常重启和卸载保护验证。不要接触作者正在使用的应用。
6. 精确提交并检查树，普通 push 更新 main；禁止 force push、重写已发布标签或覆盖既有 Release 资产。
7. 对同一提交创建 vX.Y.Z 标签。在 Actions 手动运行 Windows Release，输入已有标签；release.yml 创建**草稿预发布**及安装包/摘要，等待安装与下载验收后再公开。
8. 下载实际附件，核验 SHA-256 与版本，再发布草稿。Actions artifact 不等于 Release 下载。
9. 最后检查公开仓库、README、徽章、Release 与在线链接。

维护者可使用已授权的 GitHub API 上传同一提交的本地验证产物，必须保留构建记录和摘要；无需在源码放置 PAT。若 CI 已生成同名资产，先核验而非覆盖。没有证书的版本必须标明未签名；使用 SHA-256 只能验证字节一致，不能冒充签名。

0.1 使用 v0.1.0 开发预览标记。未来版本通过新提交和新标签改进，不把首版称为全 V3 完成。
